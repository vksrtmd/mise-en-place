---
name: retro
description: "Conduct a retrospective on a coding session and suggest improvements to its environment. Use only when the user asks for a retro."
---

Suggest improvements to the coding agent's **environment** as candidates; the user applies the ones they pick.

## Steps

1. Read the primary sources for each session the user names, else for the current one; after a `/clear`, when the current session holds only this retro, the session its `⟲` row in `sessions.sh` names. A vague count ("recent sessions") names the latest day's sessions before this one, at most 8. Run the substeps once per session.

   1. Find the logs. A session's log is `~/.claude/projects/<project>/<session id>.jsonl`, where `<project>` is the start directory mapped as in `sessions.sh --help`; its subagent transcripts sit in `<session id>/subagents/agent-*.jsonl`. The current session is the newest `.jsonl` there (with sessions running in parallel, the one holding a phrase from this conversation). For sessions the user names by what they did ("the /implement 20 run", "the two before this one"), run [`scripts/sessions.sh`](scripts/sessions.sh) on the project dirs and match the description against its lines; "the session before this clear" is the id on the clear's `⟲` row.
   2. Write the files. Read `scripts/digest.py --help` first. Into a `mktemp -d` directory outside the repository, write [`scripts/digest.py`](scripts/digest.py) and `digest.py --to-read`, each on the `<session id>` directory (on the `.jsonl` when the session dispatched no subagents), and `digest.py --text <main.jsonl> 2000`, the orchestrator's prose (the default width cuts long reasons). When the main log is still in your context, you hold every line of it: skip `--text`, and with no subagents write only `digest.py <main.jsonl>` (its stats and friction).
   3. Read the files with the Read tool (a Bash result over the inline limit costs a round-trip). Read the `--text` file first, when you wrote it: the orchestrator's prose explains most causes. Then the digest by `## ` section: the summary sections and the main block. Pick the agents to read: the top 3 of `## agents by out tokens`, and any agent the summary or the main log points at. Read each one's block: its prompt, friction and report. When any of these mentions meant red tests (red-first tests, mutation runs), or meant reds still show as `!` (the `--to-read` file's `note:` line names agents briefed for red tests), rewrite the digest and the `--to-read` file with `EXPECTED_RED='<regex of their commands>'` before reading any window.
   4. Read the windows in the `--to-read` file of the main log, which holds every user turn and most friction, and of the agents you picked. When the main log is still in your context, you hold every line of it: take its causes from there, citing each by the `@line` that `digest.py --calls <main.jsonl>` prints beside its call, and read only the agents' windows. Where a window leaves the cause open, widen it (the file's `widen:` command), list the agent's tool calls with `digest.py --calls <transcript>`, or read the transcript. A `?` its window shows to be quoted text is clean. An `also:` line's groups take the cause of the window above it. The summary's repeated-friction and hedges sections stand for the agents you leave unread.

   With 3 or more sessions, read none of them in this context: launch one Sonnet subagent (`model: "sonnet"`) per session, all in one batch, to run substeps 1–4 on it, handing it this file's path (`~/.claude/skills/retro/SKILL.md`), the session id and its project dir. Its report, its final message after its last tool call (the handback carries only that message), holds: each window's cause as the window shows it, cited `<agent id8 or main> @line[ ×N]`; verbatim with its cite, each `⏸` and `⌛` line, each user turn that stopped or corrected the run, and each hook block; the hedges it judges real; each rule of `~/.claude/rules/global.md`, the repo's `CLAUDE.md` and the skills the session loaded that the session broke, and each it put to the test and kept; the branches, worktrees and PRs the session created; and the digest's stats lines. Step 2 works from those reports, opening a transcript only where a report leaves a cause open.

   Done when every session's report is in (with subagents), or else when the summary, the main block, and the blocks and windows of the agents you picked are read, and every main-log window is read or held in context, each window's cause stated as it shows it and cited by `@line`, a group (`×N`) by the window that stands for it. Then, once per retro after the last session, when the retro covers several sessions, tell the user which sessions and agents you read and the top themes so far, and go on to step 2 in the same turn.

2. Collect candidates. Start from these signals:

   - **Stops**: every point where the run waited on the user (a rejected push, a question, a denied permission, a "stop it" among the digest's user turns) or on a usage limit (the digest's `⏸` lines, with how long each paused) or on a long wait (its `⌛` lines). Each is a candidate on its own. When a `⏸` line's out tokens read `none`, name the sessions other than this one whose span in `scripts/sessions.sh` overlaps the 5 hours before the pause's `at` time, and make it an Orchestration candidate about running them in parallel. A pause's waiting minutes measure the orchestrator's late resume: their fix resumes the agents as soon as the limit lifts. A conflict stop whose cause is the base moving while the run was open (the user merged another PR) is a candidate for checking the PR still merges before reporting it (the **Check a PR still merges** bullet of `~/.claude/docs/issue-tracker.md`, when it exists).
   - **Interruptions**: every run cut short from outside (a crash, a killed agent). Note what was lost and how it was resumed, and ask what would have made the resume cheaper. A lost handback (empty, a placeholder, or cut by a safety classifier) is fixed in the brief: the agent reports as its final message, in short sections that describe each finding by file, line and effect; a report that names security holes goes to a file under `/tmp`, handed back as its path (the reason is in the code-review skill's `findings.md`, when installed).
   - **Broken rules**: every rule in the steering files and in the skills the session loaded that the run didn't follow. Reread each rule against the session; ask of each break why it slipped. With several sessions, count those that broke each rule and those that kept it: a rule more than half of them broke doesn't fit the work: its candidate fixes it per Steering files and skills, citing each session counted. Check every hook block too: when a steering file or skill prescribes the command the hook blocked, that is a candidate; a block of a command that changes nothing the hook guards (text in a commit message, an echo) is a hook bug: an Automated checks candidate, with that command as a new case in the hook's test.
   - **Late defects**: every defect found after the work was called done: a `/code-review` finding, a user correction (read the digest's user turns for it), the orchestrator's own spot check. Ask of each what check, doc or navigation pointer would have prevented it.
   - **Hedges**: every report sentence where an agent assumed, skipped a check or could not find out; the digest's hedges section lists them. Each marks information the agent lacked: ask what would have given it. A gap the agent's brief ordered (its limits print above its hedges) is a Briefs candidate when the limit cost the run, else clean.
   - **Left state**: what any session left on the user's side: `git worktree list`, local branches, open PRs, background tasks still running. A worktree or branch whose PR is merged or closed (`gh pr list --head <branch> --state all`), and a task no live run owns, is finished work left behind: its candidate names the cleanup rule that should have removed it. When its PR merged or closed after the session's last entry (`gh pr list --head <branch> --state all --json mergedAt,closedAt`), no rule broke: list it under leftovers (step 3), not as a candidate.
   - **Repeats across agents**: the same goal pursued in several transcripts, by whatever commands. The digest's repeated-commands section catches identical commands and its friction-repeated section the same error; for the same hunt by different commands, compare the reports of the agents you read.

   Confirm each cause in the environment (a mount, a permission, a timeout or size cap) with one command where the session ran before a candidate names it; from elsewhere, mark the candidate **unverified** and open its Change (step 3) with the command that settles the cause. The session that applies it runs that command first and drops the candidate when its output doesn't confirm the cause.

   Then sort each candidate into a category:

   - **Navigation**: a **navigation pointer** (a line, in a file the agent already reads, naming where the information lives), or a hidden dependency between files made explicit. _Use when_ the session took a long time to find a piece of information.
   - **Automated checks**: a **mechanical** mistake (a fixed syntactic pattern, a banned API, an import shape, a file-location rule) gets a deterministic check: a lint rule, a type, a test, a filesystem linter, a pre-commit hook or a CI job, whichever the repo's language and existing guardrail make cheapest. Read the repo's own check command first: a check that exists but sits unwired or silently broken is the finding, and the fix is to wire or repair it. A repo with no **guardrail** (no pre-commit hook and no CI job running its lint/typecheck/test command) is itself a finding. _Use when_ the agent made a mistake a check could have caught, or the repo has no guardrail.
   - **Steering files and skills**: the repo's and the user's global `AGENTS.md` / `CLAUDE.md`, and the skills the session loaded. A **judgement call** no check can catch (cross-file consistency, matching the surrounding style) becomes a rule in the file the implementer loads when it touches the code the rule governs: a rules file scoped to those paths (one with `paths:` frontmatter, such as `.claude/rules/*.md`) when the repo has a rules directory, else the repo's `AGENTS.md`/`CLAUDE.md`, with a long rule in a doc behind a pointer there. Fix each rule by why it slipped: an unchecked mechanical one moves out to a check, an ambiguous one is reworded, a buried one moves to where the agent reads it (the file's top, or a pointer in the skill or doc for that work), and one that misfired (applied where it doesn't fit) is clarified or removed. Delete the no-ops (instructions that don't change the agent's behaviour) you meet on the way. _Use when_ a broken or misfired rule or a late defect traces to a rule in one of them, or to a judgement call no file states.
   - **Tool economy**: a cheaper form of an expensive call, or of custom tooling (CLIs, MCPs) that spends tokens it needn't. _Use when_ the digest's stats show a large result (`largest N KB`), or an agent's out tokens stand far above the rest.
   - **Information access**: ways to give the agent information it lacked: teeing dev server logs, read-only access to third-party services. _Use when_ a crucial piece of information was not available to the agent.
   - **Briefs**: what a subagent's prompt lacked or got wrong, and collisions between parallel agents (two branches touching the same lines). The fix lands in the dispatching skill or its checklist for writing briefs, where the next fan-out reads it; when the session loaded no dispatching skill, in the user's global steering file. _Use when_ an agent corrected or worked around its brief, or parallel work conflicted.
   - **Orchestration**: what the run cost to dispatch: the model each agent ran on, how many ran at once, and how the run fit the usage quota. The fix lands where a Briefs fix does: a smaller model for a mechanical task, fewer agents in parallel, the work split across quota windows. Cite each pause's tokens per model as its `⏸` line prints them (out tokens since the previous pause), and the work they bought. _Use when_ an agent ran on a bigger model than its task needed, or the run hit a usage limit.

   Done when every signal and every category has been checked against the session, and each has candidates, each citing the transcript moment that shows it, or is named clean. With no subagents, Repeats across agents and Briefs are clean.

3. Present the candidates to the user, grouped by destination repository and numbered from 1 in each group by **severity** (how often it will recur in future sessions × what it costs: a stop that waited on the user, or a broken rule that changed the user's state (checkout, tracker, pushed refs), outranks wasted tool calls, which outrank wasted tokens). A candidate ranked above one this order puts higher says why in one clause.

   - Groups: **This repo** first, the repository the session worked in, which also takes the fixes for an installed file it is the source of. Then one group per other source repository, headed by its name, found from the README or `CLAUDE.md` of the installed file's directory, which names its source repository; a file with no known source goes in a group headed by its path.
   - The user carries each candidate into a fresh session (after `/clear`, or in that repository), so write it to stand alone, for a reader with none of this retro's context: File · Change · Why · Cites `<project>/<session id>` · `<agent id8 or main> @line[ ×N]`, the full session id.
   - A **near miss**, a mistake caught before it cost anything, is labelled so.
   - Cite figures as the digest prints them (stats, `⏸` lines, `×N`, friction-repeated agent and line counts).
   - After the candidates, list as **leftovers**, unnumbered, fixes to this run's own output (a PR body, an unfinished commit) and work whose PR merged or closed after its session ended.
   - End with the line `clean: <names>`, listing only the signals and categories with no candidate (`clean: Stops, Interruptions, Briefs`).

   Done, and the retro ends, when the candidates are presented, near misses come last in each group, and the `clean:` line names every clean signal and category.
